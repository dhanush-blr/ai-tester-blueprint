# Requirements Discovery - Test Strategy Builder AI Agent

This document contains the definitive engineering questionnaire for Phase 1 (Requirements Discovery). The responses to these questions establish the technical architecture, core behavior, schema specifications, and integration boundaries for the decoupled **Test Strategy Builder AI Agent**.

---

## 🟢 B.L.A.S.T. Core Discovery Questions

### 1. North Star
*   **Question:** What is the singular, non-negotiable desired outcome of the Test Strategy Builder AI Agent?
*   **Response:** Automatically fetch a Jira issue ticket, ingest its engineering context, and generate a comprehensive, boardroom-ready Quality Assurance Test Strategy document using the Groq LLM pipeline.

### 2. Integrations
*   **Question:** What external services, repositories, or tracking platforms (e.g., Jira, Slack, GitHub, Confluence) must this application connect to? Are API keys, endpoints, and credentials ready?
*   **Response:** Direct basic authentication integration with Atlassian Jira Cloud APIs (Jira URL, Email, Token) and downstream server authentication via the Groq SDK gateway.

### 3. Source of Truth
*   **Question:** Where does the primary input data for generating a test strategy live? (e.g., custom user text inputs, scanned repositories, architectural specification files, uploaded design documents, or specific API feeds?)
*   **Response:** The live operational Atlassian Jira ticket description and metadata fields retrieved dynamically via the backend proxy layer using user-supplied Jira IDs (e.g., KAN-4).

### 4. Delivery Payload
*   **Question:** How and where should the final test strategy result be delivered and saved? (e.g., download as a standard Markdown file, save to a dedicated `/output` directory on the server, post via Webhook to Slack/Teams, or write to an external database?)
*   **Response:** An interactive client-side rich typographical preview pane powered by `react-markdown` alongside a single-click local Markdown (.md) text blob download mechanism.

### 5. Behavioral Rules
*   **Question:** What are the key behavioral constraints for the generation agent? (e.g., specific writing tone, target word limits, "do-not-hallucinate" rules, strict format validation constraints?)
*   **Response:** The generation engine must output an analytical, formal quality engineering framework, mapping concrete verification tools to the tech stacks found, organizing outputs into clear markdown tables, and enforcing zero-hallucination guardrails.
